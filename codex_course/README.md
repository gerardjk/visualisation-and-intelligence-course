# Visualisation and Intelligence

This folder contains a six-session version of the course. Each session is designed for three hours and combines a concise slide story, a worked demonstration, a Copilot-friendly notebook, critique or repair work, and an exit ticket.

Session folders and documents use descriptive titles rather than class or lecture numbers.

## Course documents

- [Course plan](COURSE_PLAN.md)
- [Seeing Data](seeing_data/)
- [Choosing Visual Forms](choosing_visual_forms/)

The remaining sessions are specified in the course plan and can be developed using the same structure.

## Developed teaching packs

Each developed session now includes:

- an editable PowerPoint deck;
- a primary student notebook with open tasks;
- a supported starter notebook for students blocked by syntax;
- an executable instructor solution notebook;
- a detailed teaching plan and instructor guide;
- a worked demonstration;
- concrete activity artefacts and suggested answers;
- timing checkpoints, extensions, misconceptions and assessment mapping.

Distribute the primary student notebook at the start of the lab. Keep the supported starter as an intervention. Do not distribute the instructor notebook until the activity and any related assessment have concluded.

## Standard session rhythm

| Time | Mode | Purpose |
|---|---|---|
| 0:00–0:45 | Concepts and examples | Establish the session argument and vocabulary |
| 0:45–1:15 | Worked demonstration | Model a complete analytical or design decision |
| 1:15–1:25 | Break | — |
| 1:25–2:25 | Notebook lab | Use Copilot within explicit constraints and verification checks |
| 2:25–2:50 | Critique and repair | Compare, test, redesign or review |
| 2:50–3:00 | Exit ticket | Record a decision, limitation and next action |

## Notebook design rules

Every notebook asks students to:

- predict an output before generating code;
- give Copilot a bounded task and explicit requirements;
- retain the prompt or a short prompt summary;
- test row counts, types, missing values and transformations;
- distinguish observations from interpretations;
- explain at least one generated code block;
- record what was accepted, modified or rejected;
- disclose limitations that remain.
