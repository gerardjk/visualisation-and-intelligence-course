# Six-session course plan

## Course proposition

A visualisation is not merely a picture of data. It is a designed claim that connects evidence, visual encoding, interpretation, audience and action. Intelligent tools can accelerate production, but students remain responsible for specifying, checking, repairing and defending the result.

The repeated workflow is:

```text
Question → Evidence → Visual task → Visual form → Interaction → Verification → Disclosure → Defence
```

## Session map

| Session | Core question | Main content | Studio output |
|---|---|---|---|
| Seeing Data | How do charts create meaning? | Anscombe, Snow, AIATSIS, Bertin, human and machine interpretation | Verified chart critique |
| Choosing Visual Forms | What visual task are we performing? | Visual Vocabulary, tidy data, magnitude, distribution, correlation, time and colour | Three-chart comparison and justified selection |
| Narrative, Audience and Dashboards | Who is this for and what do they need to do? | Personas, user stories, Gestalt grouping, hierarchy, Tableau and dashboard patterns | Dashboard plan and prepared dataset |
| Interactive and Specialised Visualisation | When does interaction add genuine value? | Streamlit, maps, flows, networks, animation, web graphics and simpler alternatives | Interactive prototype and specialisation decision |
| AI, Uncertainty and Responsible Interpretation | How do we know an interpretation is justified? | Generated insight, uncertainty, missingness, accessibility, provenance and data governance | Repaired chart, caption and verification report |
| Public Data Products and Defence | Can another person load it, understand it, trust it and use it? | Deployment, acceptance tests, quality review, revision, disclosure and oral defence | Release candidate and defence notes |

## Assessment thread

The sessions produce cumulative evidence rather than isolated exercises:

- critiques establish visual judgement;
- chart-selection records establish task-to-form reasoning;
- dashboard planning establishes audience and purpose;
- interactive prototypes establish implementation ability;
- verification and provenance records establish responsible tool use;
- the final review and defence establish individual understanding.

## Role of the Atlas

The Atlas is an example library, not a list to cover exhaustively. Selected entries should perform a specific teaching job:

| Teaching job | Useful entries |
|---|---|
| Show why looking matters | Anscombe’s quartet |
| Show a visual causal argument | John Snow’s cholera map |
| Introduce the visual grammar | Bertin’s visual variables |
| Discuss data governance and boundaries | AIATSIS Map of Indigenous Australia |
| Compare magnitude and distribution | Population pyramid, box plot, Gaussian, power law |
| Compare relationships and trends | Hertzsprung–Russell, Hubble, Keeling, climate stripes |
| Explain grouping and flow | Networks, trees, Sankey and process flow |
| Discuss uncertainty and prediction | Fan chart, ROC curve and confidence intervals |

## Materials pattern

Each developed session contains:

- `teaching_plan.md` — timing, outcomes, preparation and facilitation;
- `slides.md` — slide-by-slide content and speaker direction;
- an activity sheet;
- an executable `.ipynb` notebook with Copilot prompts and tests.
