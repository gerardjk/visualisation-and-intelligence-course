# Web Design and JavaScript Literacy

## Goal

Students do not need to become frontend engineers. They need enough literacy to understand that interactive visualisations are web interfaces and to know when Python/Streamlit is enough versus when web-native tools may be required.

## Basic web stack

| Layer | Role |
|---|---|
| HTML | document structure |
| CSS | appearance and layout |
| JavaScript | behaviour and interaction |
| SVG | vector drawing for charts |
| Canvas | bitmap drawing, many marks |
| WebGL | accelerated 2D/3D graphics |

## Visualisation libraries and tools

| Tool/library | Use case |
|---|---|
| D3.js | custom web visualisation |
| Vega-Lite | declarative grammar of interactive graphics |
| Altair | Python interface to Vega-Lite |
| Plotly.js | interactive charts |
| Plotly Python | Python interface to Plotly.js |
| Leaflet | web maps |
| folium | Python interface to Leaflet |
| deck.gl | large-scale geospatial WebGL visualisation |
| pydeck | Python interface to deck.gl |
| Three.js | 3D WebGL scenes |

## Interface design basics

- clear hierarchy,
- meaningful default state,
- grouped controls,
- progressive disclosure,
- visible source and limitations,
- empty states,
- error states,
- mobile and accessibility considerations.

## Week 6 decision prompt

```text
Does this project need web-native visualisation?
Could Streamlit + Altair answer the same user story more clearly?
What would JavaScript enable that Python/Streamlit does not?
```
