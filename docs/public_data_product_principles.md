# From Prototype to Public Data Product

Week 5 is not a data-engineering week. It is a public-trust week.

## Principle

A visualisation is not finished when it works on your laptop. It becomes a public data product when another person can open it, understand it, trust it, and use it.

## Technical issue as communication issue

| Technical issue | Communication/trust consequence |
|---|---|
| broken file path | user cannot access the story |
| missing dependency | app fails before interpretation begins |
| slow reloads | user abandons the app |
| no caching | interaction feels broken |
| missing values | chart may silently mislead |
| empty filter result | user cannot tell if data is absent or app is broken |
| changed source data | old interpretation may become invalid |
| no source note | user cannot verify claims |
| no AI disclosure | user cannot assess tool-mediated work |

## Public Data Product Checkpoint questions

```text
Can another person open it?
Can another person understand what it is for?
Can another person see where the data came from?
Can another person tell what the app does not show?
Can another person use the controls without breaking it?
Can another person verify how intelligent tools were used?
```
