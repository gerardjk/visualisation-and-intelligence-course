# Design Principles

## 1. Judgement before production

Intelligent tools can produce plausible charts, prose, and code quickly. The course therefore assesses whether students can judge, verify, repair, and defend visual outputs.

## 2. User stories before charts

Students begin with a user story, not a tool. The user story identifies who needs the visualisation, what they need to do, and why it matters.

## 3. Visual task before chart type

Students use the FT Visual Vocabulary to classify the task before choosing a chart.

## 4. Deployment as communication

A deployed data app is a public communication artefact. Data loading, caching, error handling, and disclosure are part of communicative trust.

## 5. Specialised visualisations are instruments, not upgrades

Maps, flows, networks, animation, and 3D receive credit when they serve a task. They do not receive credit merely for spectacle.

## 6. AI use must be visible

Students may use intelligent tools, but must document how they used them, what they accepted, what they rejected, and how they verified outputs.

## 7. Responsibility is threaded, not postponed

Week 7 provides the deep responsible-interpretation module, but every week includes a lightweight responsibility prompt.
